% C03 Digital Twin

\begin{enumerate}

\item Mechatronic System: A Mechatronic System integrates mechanical, electric/electronic systems, and associated information processing. [..] The expansion of functions possible through the integration of sensors and microcomputers and the achievement of synergetic effects are essential. Based on [VDI2206].

\item Cyber-Physical System (CPS): A Cyber-Physical System (CPS) is a "system which links real [..] objects and processes with information-processing (virtual) objects and processes via open, in some cases global, and constantly interconnected information networks".

\item Asset: An Asset is an „entity which is owned by or under the custodial duties of an organization, having either a perceived or actual value to the organization".[I40Glossary]

\item Mechatronic and Cyber-Physical Systems (MCPS): Mechatronic and Cyber-Physical Systems (MCPS)

\item Asset Administration Shell (AAS): Asset Administration Shell (AAS)

\item Real Twin: The Real Twin denotes the object of interest in the real world.

\item Digital Twin: A Digital Twin is a virtual digital 1-to-1 representation of its Real Twin viewed from a chosen point of view, that allows interaction based on up-to-date Digital Artifacts. Digital Twins can be arranged and connected in hierarchical and heterarchical structures just like their Real Twins.

\item Twin Type: A Twin Type is the exemplary description of a Digital or Real Twin.

\item Hybrid Twin: A Hybrid Twin is a MCPS consisting of the Real Twin as the real component and the Digital Twin as the virtual component.

\item Experimentable Digital Twin (EDT): An Experimentable Digital Twin (EDT) is a virtual digital 1-to-1 representation (semantics, structure, behavior, interaction) of its Real Twin (RT) viewed from a chosen point of view, that allows interaction based on experimentable models. Experimentable Digital Twins can be arranged and connected in hierarchical and heterarchical structures just like their Real Twins.

\item EDT-Component: A component of an Experimentable Digital Twin (EDT-Component for short) is a semantic unit that performs a certain function as part of an EDT. It has inputs and outputs and is networked via communication infrastructures with the other components of the EDT as well as its inputs and outputs. It has its own behavior, which is either modeled directly via suitable simulation models or is modeled via a hierarchically subordinated EDT.

\item System Component: The System Component is the functional unit of Physical System that represents its intended function and is influenced to achieve this function.

\item Actuator: An Actuator is a "device with a purposive influence on the process", here the System Component. Based on [VDI-VDE-2650-1]

\item Sensor: A Sensor is a "device that picks up physical measurement variables and converts them to standardized output signals" [VDI-VDE-2650-1].

\item Information Processing System (IPS): The Information Processing System is a functional unit that monitors the MCPS via Sensors and then influences it purposively via Actuators to perform specified tasks and to achieve desired goals.

\item UI or HMI: A User Interface (also called Human-Machine Interface) comprises "all components of an interactive system that provide information and controls for the user to accomplish specific tasks with the interactive system".[DIN-9241-110]

\item Interaction / Communication Infrastructure: The Interaction / Communication Infrastructure comprises all facilities that are necessary for the technical realization of the exchange of material, energy and information between a MCPS and its components by linking their ports via connections.

\item Port: A port models an interaction point between asystem and its environment.

\item Connection: A connection allows information, material or energy to be exchanged between two or more compatible ports.

\item Interface: The interface of a system specifies structure and behavior that the system provides or requires from its environment.[Weilkiens2014]

\item EDT-Scenario: An EDT-Scenario is a network of EDT that are connected via their ports to replicate an application scenario. They interact with each other during the simulation.

\item Emergence: Emergence occurs when an entity is observed to have properties its parts do not have on their own.

\end{enumerate}
